## 2. 제공되는 에셋 (input materials)
바로 이전 시스템 프롬프트로부터 제공된 에셋들은 다음과 같다.

### 2.1. 테스트 시나리오
```json
${{AutoBeTestScenario}}
```

적당히 설명 써주고, 여기서 타깃 endpoint 와 draft 및 dependencies 를 어떻게 사용해야하는지 말해.

그리고 functionName은 이후 e2e 테스트 함수의 이름을 구성하는데 쓰인다고 말해주고.

### 2.2. DTO 타입 정보
```typescript
/**
 * 게시물에 대한 적당한 설명.
 * 
 * 매우 상세하게 작성되어있으니, 이를 잘 읽고 그 개념을 파악하도록.
 */
export type IBbsArticle = {
  /**
   * 속성에 대한 설명이 주석으로 쓰여있다.
   */
  id: string & tags.Format<"uuid">;
  title: string;
  body: string;
  files: IAttachmentFile[];
  created_at: string & tags.Format<"date-time">;
}
export namespace IBbsArticle {
  export type ISummary = {
    id: string & tags.Format<"uuid">;
    title: string;
    created_at: string & tags.Format<"date-time">;
  };
  export type ICreate = {
    title: string;
    body: string;
    files: IAttachmentFile.ICreate[];
  };
  export type IUpdate = {
    title?: string;
    body?: string;
    files?: IAttachmentFile.ICreate[];
  };
}
```

작성해야 할 e2e 테스트 함수가 사용할 수 있는 DTO 타입들에 대한 정보가 주어진다.

위 예제코드와 같이 namespace 그룹핑이 되어있을 수 있으며, 각각의 타입 및 속성에는 그것들에 대한 설명이 주석으로 쓰여있을 수 있으니, 이들을 잘 읽어 그 용도 및 개념을 십분 이해하도록 해.

또한 각 DTO 타입들마다 어떤 값들을 채워넣어야하는지 파악하여, 추후 e2e 테스트 코드를 작성하며 잘못된 타입의 값이 들어가지 않도록 주의하자.

### 2.3. API SDK 함수

```typescript
/**
 * Update a review.
 *
 * Updadte a {@link IShoppingSaleReview review}'s content and score.
 *
 * By the way, as is the general policy of this shopping mall regarding
 * articles, modifying a question articles does not actually change the
 * existing content. Modified content is accumulated and recorded in the
 * existing article record as a new
 * {@link IShoppingSaleReview.ISnapshot snapshot}. And this is made public
 * to everyone, including the {@link IShoppingCustomer customer} and the
 * {@link IShoppingSeller seller}, and anyone who can view the article can
 * also view the entire editing histories.
 *
 * This is to prevent customers or sellers from modifying their articles and
 * manipulating the circumstances due to the nature of e-commerce, where
 * disputes easily arise. That is, to preserve evidence.
 *
 * @param props.saleId Belonged sale's {@link IShoppingSale.id }
 * @param props.id Target review's {@link IShoppingSaleReview.id }
 * @param props.input Update info of the review
 * @returns Newly created snapshot record of the review
 * @tag Sale
 * @author Samchon
 *
 * @controller ShoppingCustomerSaleReviewController.update
 * @path POST /shoppings/customers/sales/:saleId/reviews/:id
 * @nestia Generated by Nestia - https://github.com/samchon/nestia
 */
export async function update(
  connection: IConnection,
  props: update.Props,
): Promise<update.Output> {
  return PlainFetcher.fetch(
    {
      ...connection,
      headers: {
        ...connection.headers,
        "Content-Type": "application/json",
      },
    },
    {
      ...update.METADATA,
      template: update.METADATA.path,
      path: update.path(props),
    },
    props.input,
  );
}
export namespace update {
  export type Props = {
    /**
     * Belonged sale's
     */
    saleId: string & Format<"uuid">;

    /**
     * Target review's
     */
    id: string & Format<"uuid">;

    /**
     * Update info of the review
     */
    input: Body;
  };
  export type Body = IShoppingSaleReview.IUpdate;
  export type Output = IShoppingSaleReview.ISnapshot;

  export const METADATA = {
    method: "POST",
    path: "/shoppings/customers/sales/:saleId/reviews/:id",
    request: {
      type: "application/json",
      encrypted: false,
    },
    response: {
      type: "application/json",
      encrypted: false,
    },
    status: 201,
  } as const;

  export const path = (props: Omit<Props, "input">) =>
    `/shoppings/customers/sales/${encodeURIComponent(props.saleId?.toString() ?? "null")}/reviews/${encodeURIComponent(props.id?.toString() ?? "null")}`;
}
```

이것은 작성해야 할 e2e 테스트 함수가 호출할 API SDK 함수의 정의야. 이 API SDK 함수는 `api.functional.shoppings.customers.sales.reviews.update` 로 호출할 수 있어.

그리고 이 함수에서 특히 namespace 내의 `Props` 타입을 잘 봐야해. AI 너가 API SDK 함수를 호출할 때, 어떤 property 들을 넣어야 하는지, 그리고 그 property 들의 타입은 무엇인지 이를 통해 알 수 있어.

## 3. 생성해야 할 코드
### 3.1. 테스트 함수 정의

```typescript
/**
 * [Clearly explain test purpose]
 * 
 * [Explain business context and necessity]
 * 
 * [Step-by-step process]
 * 1. First step
 * 2. Second step
 * ...
 */
export async function test_api_{domain}_{functionName}(
  connection: api.IConnection,
) {
  // Implementation for each step
}
```

E2E 테스트 파일을 생성할 때, 위와 같이 `export async function test_api_{domain}_{functionName}` 로 시작하는 함수를 정의하고, 오직 단 하나의 파라미터 `connection: api.IConnnection` 만을 선언해준다. 여기서 domain 은 AI 너가 function calling 하면서 정의하게되는 속성 `IAutoBeTestWriteApplication.IProps.domain` 이고, functionName 은 내가 AI 너에게 주는 입력값 중 하나인 시나리오 데이터 `AutoBeTestScenario.functionName` 으로부터 와.

그리고 함수 위에는 너가 AI function calling 으로 구성하는 테스트 함수의 시나리오 정보 `IAutoBeTestWriteApplication.IProps.scenario` 를 주석으로 써 주렴. 만약 시나리오의 서술 정보가 테스트 함수를 설명하는 주석으로 어울리지 않는다 판단되면, 너가 고쳐써도 좋아.

이외에 함수 바깥으로는 위 시나리오 주석 외에 그 어떠한 코드도 작성해서는 안 돼. import 문이나 함수 바깥으로의 또다른 함수 정의 내지 변수 선언 등을 하지 말도록. import 문은 AI 가 코드를 작성한 후 로직에서 자동으로 채워줄것이고, 사용자 정의 함수가 필요하거든 함수 내 함수로써 정의하도록.

### 3.2. API SDK 함수 호출

```typescript
export async function test_api_shopping_sale_review_update(
  connection: api.IConnection,
) {
   const article: IBbsArticle = await api.functional.bbs.articles.create(
    connection, 
    {
      service: "debate", // path parameter {service}
      section: "economics", // path parameter {section}
      body: { // request body
        title: RandomGenerator.paragraph()(),
        body: RandomGenerator.content()()(),
        files: ArrayUtil.repeat(
          typia.random<number & tags.Format<"uint32"> & tags.Maximum<3>>(),
        )(() => {
          return {
            url: typia.random<string & tags.Format<"uri">>(),
          };
        }),
      } satisfies IBbsArticle.ICreate,
    },
  );
  typia.assert(article);
}
```

이전의 시스템 프롬프트에 주어진 API 함수들을 사용하면 되며 (`api.functional...()`), 반드시 첫번째 파라미터로는 `connection` 변수를 삽입해야 한다. 그리고 API 함수의 두번째 파라미터는 없거나, 또는 object 타입이야.

먼저 두번째 파라미터가 아주 없는 경우는, 해당 API 에 request body 도 없고 그 어떤 path parameter 도 없는 경우야. 반대로 request body 던 path parameter 던 하나라도 있다면, 이는 keyworded parameter 의 형태로써 single object type 으로 작성해야 해.

그리고 여기서 두번째 파라미터 오브젝트를 구성할 때, API path parameter 들은 그들의 path name 이 곧 키값이야. 또한 requestBody 의 키값은 `body` 이며, 이 `body` 데이터를 구성할 때는 `satisfies RequestBodyDto` 를 붙여줌으로써, 그 타입의 안정성을 담보하도록 해.

마지막으로 호출 대상 API SDK function 이 리턴타입을 가지고 있다? 그럼 함수 호출 결과를 변수에 담아 저장한 후, 곧바로 `typia.assert(variable)` 함수를 호출, 리턴값의 타입 안정성 또한 담보해주도록 해. 물론 대상 API SDK function 의 리턴 타입이 `void` 라면, 변수에 할당할 필요도 없고 `typia.assert(variable)` 함수를 부를 일도 없겠지.

### 3.3. 랜덤 데이터
#### 3.3.1. Numeric Value
숫자에 대한 랜덤 값을 만들때면, 아래와 같이 `number` 타입에 intersection (`&`) 으로 제약들을 추가하면 된다.

  - 사용 가능 태그
    - `tags.Type<"int32">` 또는 `tags.Type<"uint32">`
    - `tags.Minimum<N>` 또는 `tags.ExclusiveMinimum<N>`
    - `tags.Maximum<N>` 또는 `tags.ExclusiveMaximum<N>`
    - `tags.MultipleOf<N>`
  - 사용례
    - `typia.random<number>()`
    - `typia.random<number & tags.Type<"uint32">>()`
    - `typia.random<number & tags.Type<"uint32"> & tags.Minimum<100> & tags.Maximum<900>>()`
    - `typia.random<number & tags.Type<"uint32"> & tags.ExclusiveMinimum<100> & tags.ExclusiveMaximum<1000> & tags.MultipleOf<10>>()`

#### 3.3.2. String Value
첫째로 `typia.random<string & tags.Format<$title>>()` 형태로 랜덤 값을 만들 수 있다.

  - 사용례
    - `typia.random<string & tags.Format<"email">>()`
    - `typia.random<string & tags.Format<"uuid">>()`
  - 사용 가능한 값
    - `binary`
    - `byte`
    - `password`
    - `regex`
    - `uuid`
    - `email`
    - `hostname`
    - `idn-email`
    - `idn-hostname`
    - `iri`
    - `iri-reference`
    - `ipv4`
    - `ipv6`
    - `uri`
    - `uri-reference`
    - `uri-template`
    - `url`
    - `date-time`
    - `date`
    - `time`
    - `duration`
    - `json-pointer`
    - `relative-json-pointer`

그리고 RandomGenerator 의 static 함수들을 이용해서도 특수 목적의 string value 를 만들 수 있다. 단, 이들 중 일부는 커링 함수의 형태이기 때문에, 사용할 때 세심한 주의가 필요하다. 필히 `node_modules/@nestia/e2e/lib/RandomGenerator.d.ts` 의 타입 정의를 확인해가며 쓸 것.

- `RandomGenerator.alphabets()`
- `RandomGenerator.alphaNumeric()`
- `RandomGenerator.mobile()`
- `RandomGenerator.name()`
- `RandomGenerator.paragraph()()`
- `RandomGenerator.content()()()`

마지막으로 정규식 패턴을 기반으로 random 값을 만드려거든, `typia.random<string & tags.Pattern<"value">>()` 를 사용하면 됨.

#### 3.3.3. Array Instance
`ArrayUtil` 의 다음 static 함수들을 사용하여, 배열을 만들 수 있다.

그런데 이 `ArrayUtil` 함수들은 커링 함수이기에, 사용할 때 세심한 주의가 필요하다. 반드시 `node_modules/@nestia/e2e/lib/ArrayUtil.d.ts` 의 타입 정의를 확인하고 용할 것.

- `ArrayUtil.repeat(3)(() => ({ name: RandomGenerator.name() }))`
- `ArrayUtil.asyncRepeat(10)(async () => { ... })`
- `ArrayUtil.asyncMap(array)(async (elem) => { ... })`
- `ArrayUtil.asyncFilter(array)(async (elem) => { ... })`

또한 배열로부터 임의 원소를 선택하거나, 또는 N 개의 원소만을 부분 추출하려거든, `RandomGenerator` 의 아래 함수들을 사용하면 된다. 이 역시 `node_modules/@nestia/e2e/lib/RandomGenerator.d.ts` 의 타입 정의를 확인해가며 사용할 것.

- `RandomGenerator.pick(array)`
- `RandomGenerator.sample(array)(3)`

### 3.4. Logic Assertion
```typescript
TestValidator.equals("x equals y")(3)(3);
TestValidator.notEquals("x and y are different")(3)(4);
TestValidator.predicate("assert condition")(3 === 3);
TestValidator.error("error must be thrown")(() => {
  throw new Error("An error thrown");
});
```

로직 검증을 위한 assertion 이 필요하면 아래 함수들을 사용하면 되.

단, 이들은 커링 함수이다보니 사용할 때 세심한 주의가 필요해. 따라서 아래 `TestValidator` 함수들을 사용할 때면, 반드시 `node_modules/@nestia/e2e/lib/TestValidator.d.ts` 의 타입 정의를 확인해가며 코드를 작성해 줘.

- `TestValidator.equals("title")(x)(y)`
- `TestValidator.notEquals("title")(x)(y)`
- `TestValidator.predicate("title")((a && b) || c)`
- `TestValidator.error("title")(async () => { ... })`

그리고 만일 이들로는 충당되지 않는 assertion 이 필요하다면, 가감없이 `if condition` 을 통해 구현하도록 해.

```typescript
if (condition)
  throw new Error("message");
```

### 3.5. 인증
```typescript
export async function test_api_shopping_sale_review_update(

  // connection.headers.Authorization 에 인증 토큰값이 알아서 할당됨
  typia.assert(seller);

```

API 함수로부터 인증 토큰이 발급되거든, 내장된 SDK 라이브러리가 알아서 connection 객체의 headers 부문에 인증 토큰을 저장해.

따라서 너는 인증 토큰에 대하여 일절 신경쓸 필요가 없고, 다만 너의 필요에 의해 필요한 API SDK 함수들만을 워크플로우에 따라 호출하면 될 뿐이야.

### 3.6. 예제 코드
```typescript
/**
 * Validate the modification of review posts.
 *
 * However, the fact that customers can write review posts in a shopping mall means 
 * that the customer has already joined the shopping mall, completed product purchase 
 * and payment, and the seller has completed delivery.
 *
 * Therefore, in this test function, all of these must be carried out, so before 
 * writing a review post, all of the following preliminary tasks must be performed. 
 * It will be quite a long process.
 *
 * 1. Seller signs up
 * 2. Seller registers a product
 * 3. Customer signs up
 * 4. Customer views the product in detail
 * 5. Customer adds the product to shopping cart
 * 6. Customer places a purchase order
 * 7. Customer confirms purchase and makes payment
 * 8. Seller confirms order and processes delivery
 * 9. Customer writes a review post
 * 10. Customer modifies the review post
 * 11. Re-view the review post to confirm modifications.
 */
export async function test_api_shopping_sale_review_update(
  connection: api.IConnection,
): Promise<void> {
  // 1. Seller signs up
  const sellerEmail: string = typia.random<string & tags.Format<"email">>();
  const seller: IShoppingSeller = 
    await api.functional.shoppings.sellers.authenticate.join(
      connection,
      {
        body: {
          email: sellerEmail,
          password: "1234",
          nickname: RandomGenerator.name(),
          mobile: RandomGenerator.mobile(),
        } satisfies IShoppingSeller.IJoin,
      },
    );
  typia.assert(seller);

  // 2. Seller registers a product
  const sale: IShoppingSale = 
    await api.functional.shoppings.sellers.sales.create(
      connection,
      {
        body: {
          name: RandomGenerator.paragraph()(),
          description: RandomGenerator.content()()(),
          price: 10000,
          currency: "KRW",
          category: typia.random<"clothes" `electronics" `service">(),
          units: [{
            name: RandomGenerator.name(),
            primary: true,
            stocks: [{
              name: RandomGenerator.name(),
              quantity: 100,
              price: 10000,
            }],
          }],
          images: [],
          tags: [],
        } satisfies IShoppingSale.ICreate,
      },
    );
  typia.assert(sale);

  // 3. Customer signs up
  const customerEmail: string = typia.random<string & tags.Format<"email">>();
  const customer: IShoppingCustomer = 
    await api.functional.shoppings.customers.authenticate.join(
      connection,
      {
        body: {
          email: sellerEmail,
          password: "1234",
          nickname: RandomGenerator.name(),
          mobile: RandomGenerator.mobile(),
        } satisfies IShoppingCustomer.IJoin,
      },
    );
  typia.assert(customer);
  
  // 4. Customer views the product in detail
  const saleReloaded: IShoppingSale = 
    await api.functional.shoppings.customers.sales.at(
      connection,
      {
        id: sale.id,
      },
    );
  typia.assert(saleReloaded);
  TestValidator.equals("sale")(sale.id)(saleReloaded.id);

  // 5. Customer adds the product to shopping cart
  const commodity: IShoppingCartCommodity = 
    await api.functional.shoppings.customers.carts.commodities.create(
      connection,
      {
        body: {
          sale_id: sale.id,
          stocks: sale.units.map((u) => ({
            unit_id: u.id,
            stock_id: u.stocks[0].id,
            quantity: 1,
          })),
          volume: 1,
        } satisfies IShoppingCartCommodity.ICreate,
      },
    );
  typia.assert(commodity);

  // 6. Customer places a purchase order
  const order: IShoppingOrder = 
    await api.functional.shoppings.customers.orders.create(
      connection,
      {
        body: {
          goods: [
            {
              commodity_id: commodity.id,
              volume: 1,
            },
          ],
        } satisfies IShoppingOrder.ICreate,
      }
    );
  typia.assert(order);

  // 7. Customer confirms purchase and makes payment
  const publish: IShoppingOrderPublish = 
    await api.functional.shoppings.customers.orders.publish.create(
      connection,
      {
        orderId: order.id,
        body: {
          address: {
            mobile: RandomGenerator.mobile(),
            name: RandomGenerator.name(),
            country: "South Korea",
            province: "Seoul",
            city: "Seoul Seocho-gu",
            department: RandomGenerator.paragraph()(),
            possession: `${typia.random<number & tags.Format<"uint32">>()}-${typia.random<number & tags.Format<"uint32">>()}`,
            zip_code: typia.random<
              number 
                & tags.Format<"uint32"> 
                & tags.Minimum<10000> 
                & tags.Maximum<99999>>()
              .toString(),
          },
          vendor: {
            code: "@payment-vendor-code",
            uid: "@payment-transaction-uid",
          },
        } satisfies IShoppingOrderPublish.ICreate,
      },
    );
  typia.assert(publish);

  // Switch to seller account
  await api.functional.shoppings.sellers.authenticate.login(
    connection,
    {
      body: {
        email: sellerEmail,
        password: "1234",
      } satisfies IShoppingSeller.ILogin,
    },
  );

  // 8. Seller confirms order and processes delivery
  const orderReloaded: IShoppingOrder = 
    await api.functional.shoppings.sellers.orders.at(
      connection,
      {
        id: order.id,
      }
    );
  typia.assert(orderReloaded);
  TestValidator.equals("order")(order.id)(orderReloaded.id);

  const delivery: IShoppingDelivery =
```
