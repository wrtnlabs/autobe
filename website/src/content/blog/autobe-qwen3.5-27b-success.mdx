## Why Every Model Scores the Same

Look at that benchmark chart. The scores are almost uniform across all models. That's not a coincidence — it's by design.

AutoBe fixes the output shape. Every model fills the same AST structure, and the compiler rejects anything that doesn't fit. The model's "personality" gets erased — what survives is only what the compiler approves. So `qwen3.5-27b` and `claude-sonnet-4.6` produce nearly identical backends. Bigger models just need fewer retries.

**Different models, same result.** Self-host and the cost drops to electricity.

## How It Works

### The Problem: Compound Effects Kill Free-Form Generation

Ask an LLM to write a backend with 400 interdependent components — database schema, API endpoints, type definitions, controllers, tests. Even if each component has 95% accuracy, the probability of the whole system working is:

**0.95^400 ≈ 0.000000000000000013**

That's effectively zero. This is why "vibe coding" tools generate code that looks right but doesn't compile. One wrong type cascades through the entire codebase.

### The Solution: AST + Compiler Feedback Loops

AutoBe doesn't ask LLMs to write free-form code. Instead, LLMs fill structured AST (Abstract Syntax Tree) nodes through function calling — database schemas, API specs, test definitions, implementation code.

Here's what one of those structures looks like — the test expression type that LLMs fill:

```typescript
export namespace AutoBeTest {
  export type IExpression =
    | IBooleanLiteral   | INumericLiteral    | IStringLiteral     // literals
    | IArrayLiteralExpression  | IObjectLiteralExpression         // compound literals
    | INullLiteral      | IUndefinedKeyword                       // null/undefined
    | IIdentifier       | IPropertyAccessExpression               // accessors
    | IElementAccessExpression | ITypeOfExpression                // access/operations
    | IPrefixUnaryExpression   | IPostfixUnaryExpression          // unary operations
    | IBinaryExpression                                           // binary operations
    | IArrowFunction    | ICallExpression    | INewExpression     // functions
    | IArrayFilterExpression   | IArrayForEachExpression          // array operations
    | IArrayMapExpression      | IArrayRepeatExpression           // array operations
    | IPickRandom       | ISampleRandom      | IBooleanRandom     // random generation
    | IIntegerRandom    | INumberRandom      | IStringRandom      // random generation
    | IPatternRandom    | IFormatRandom      | IKeywordRandom     // random generation
    | IEqualPredicate   | INotEqualPredicate                      // assertions
    | IConditionalPredicate    | IErrorPredicate;                 // assertions
}
```

Four AI-native compilers (Database, OpenAPI, Test, TypeScript) validate every output. When something fails, the compiler doesn't just say "error" — it generates structured diagnostics pinpointing exactly which node failed and why. The LLM corrects only the broken parts and resubmits.

This loop repeats until every compiler says "pass."

### Why Small Models Win on Cost

Each retry on Qwen 3.5-27B costs almost nothing. A frontier model might get it right in 2 attempts; Qwen might need 5. But 5 × $0.195 is still drastically cheaper than 2 × $5. The compiler doesn't care which model generated the code — it only cares whether it compiles.

> *"If you can verify, you converge."*
